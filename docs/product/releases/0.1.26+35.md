## Cause and change

The preserved 0.1.25 bundle was installed over an older Indigen version on an Android emulator. Every launch ended before Flutter's first frame. Android's fatal log reported `androidx.startup.InitializationProvider` failing to create `androidx.work.impl.WorkDatabase`. The 0.1.25 R8 `usage.txt` listed `androidx.work.impl.WorkDatabase_Impl`'s public no-argument constructor as removed, although WorkManager creates that class by reflection during process startup.

`apps/mobile/android/app/proguard-rules.pro` now keeps that constructor. The 0.1.26 R8 `usage.txt` no longer lists it as removed, and `seeds.txt` lists `WorkDatabase_Impl()` as retained. The app version was raised to 0.1.26+35 so Play can accept a replacement for versionCode 34. No Flutter feature behavior was changed by this hotfix; the working bundle also contains the existing uncommitted Music changes from 0.1.25.

## Installed release check

Bundletool generated device-specific APKs from the signed 0.1.26 bundle using the upload key, then installed them over the emulator's 0.1.25 copy without clearing app data. The installed package reported `versionCode=35` and `versionName=0.1.26`. Android's `pidof` found the app process alive after launch, `dumpsys activity` showed `MainActivity` resumed, and the captured screen showed the Community tab with loaded content. The new log showed WorkManager initialization and no fatal startup exception. The screenshot is `.tmp/indigen-startup-0.1.26.png` (local diagnostic, not a release asset).

This verifies a local emulator update path. A physical-phone check and Google Play testing-track rollout remain pending. The user's report establishes that 0.1.25 was delivered through a testing track; Play Console status was not independently read here.
