## Contradictions and stale claims to display explicitly

1. **Three versus four products is intentional:** three public products plus one internal Admin. Do not report Admin as an additional public product (`docs/product/product-boundaries.md:5`, `:35-48`).
2. **Hosting map is incomplete relative to release receipts:** the architecture map lists website/Admin/Studio (`docs/architecture/hosting-and-domains.md:13-19`), while the 2026-10-09 release explicitly includes a `kasem-dictionary` site (`docs/operations/release-0.1.31-40.md:62`, `:80-84`). Verify full live target inventory before treating that map as exhaustive.
3. **Current Android production ID differs from old generic project facts:** September `next-five-upgrades.md:7-9` calls application ID `world.indigen.mobile`; current production flavour overrides it to `com.indigenworld.indigen` (`apps/mobile/android/app/build.gradle.kts:141-142`) and verified AAB agrees (`docs/product/releases/0.1.32+41.md:42`).
4. **Repository presence/build does not establish Play:** current app 0.1.32+41/GitHub release is documented, while many old posts still say earlier bundles not uploaded. Store availability needs current Console/device evidence, not choosing one old sentence (`docs/product/releases/0.1.32+41.md:50-52`).
5. **Publication headers are stale in multiple October 10 posts:** discovery opening says “Blogger article unpublished” (`README.md:3`), but its appended 11 October publication entry supplies a real URL (`README.md:119-123`). Points/assistance/correspondence/audio have similar appended entries; index lists published URLs (`apps/updates-blog/posts/README.md:22-30`). Treat as dated documented publication, not live re-verification.
6. **Post index can contradict itself:** reliable-workflows index text says “not deployed or published” and then links the published article in the same item (`apps/updates-blog/posts/README.md:34`); detailed release note documents deployment (`docs/operations/release-0.1.31-40.md:3-6`). Prefer latest specific receipt, retain contradiction.
7. **Labs document contains superseded experiment status:** culture-quest paragraph says implemented locally/not confirmed deployed (`docs/product/indigen-world-labs.md:40`), while dated release post says deployed October 1 with public asset checks (`apps/updates-blog/posts/2026-10-01-culture-quest/README.md:3`). 8. **Corpus ADR and API are historical baselines:** early knowledge API says two qualified approvals yield Gold (`docs/product/knowledge-workspace-api.md:35-43`), while v2 requires explicit category policies/scoped qualification and does not auto-promote old Gold (`docs/product/kawuri-corpus-implementation.md:38-39`, `:64-70`). Expose version/context.
9. **“Gold”, “published”, “training-ready”, “rewarded” and “model trained” are independent:** corpus release, source-rights grants, dataset eligibility and finance settlement each have their own gates (`docs/product/kawuri-corpus-implementation.md:48-58`; `docs/product/contributor-rewards.md:20-23`).

## Repository controls and their actual scope

- `.github/workflows/repository-checks.yml:13-24` defines committed-history gitleaks; `:32-59` checks filenames/JSON/forbidden secret and production-data names. Definition does not prove recent remote execution.
- `.github/workflows/monorepo-checks.yml:24-49` pins Node 22.12, Java 21, npm lock install, production audit, workspace types/build and contracts/governance tests.
- `.github/workflows/mobile-checks.yml:19-65` pins Flutter 3.47, regeneration/format/analyse/tests and 50% line-coverage threshold; `:73-114` defines Android/Firebase emulator integration. These are intended gates, not a current green CI claim.
- App Check guidance is stage-specific: initial tester runbook leaves it off (`docs/product/tester-readiness-runbook.md:35-37`); architecture requires staged enforcement after verification (`docs/decisions/0002-adopt-firebase-authority-with-digitalocean-api.md:25`, `:100`). “Uses App Check architecture” cannot be stated as “App Check fully enforced.”
- Stale function manifests have previously omitted poll/repost triggers; runbook requires source-export/manifest/live-function inventory comparison (`docs/product/tester-readiness-runbook.md:65-81`). The documented 10/15 news function count 223→224 is specific to that release, not a source-wide coverage measurement.
- Do not collect real data for dashboard proof. Raw community material, identities, payment details, consent evidence, recordings and production exports remain outside Git (`docs/governance/data-safety.md:5-16`). Research and dashboard fixtures must be synthetic or approved public material.

## Suggested dashboard groupings

Use evidence facets (source present / local verification reported / deployed receipt / public smoke checked / authenticated journey checked / device checked / measured outcome), with observation dates and source links. Add a “decisions needed” view for policies, rights, reviewers, finance, support and distribution. Use an explicit “no evidence captured” state for user outcome metrics. Diagrams should show the separate governance stages and the three products plus internal Admin; animation should explain those flows without suggesting that activity volume equals quality or progress toward a trained model.
